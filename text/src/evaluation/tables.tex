Each table below reports results at the operating point that achieves
$\mathrm{FPR} \leq 10^{-3}$ with the fewest bits per key
($\varepsilon = 10^{-3}$, gap-heavy query workload,
$n = \min(2^{28},\allowbreak\ |\text{dataset}|)$).
A dash (\textnormal{---}) means the filter did not reach the target FPR
within the measured parameter range.
\textbf{Bold} marks the best result in each column
(lowest BPK / lowest latency / highest throughput), excluding dashes.

\paragraph{Interpolated BPK.}
BPK is reported as the \emph{interpolated} value at $\mathrm{FPR}=10^{-3}$.
Given the last measured point above the threshold $(b_1, f_1)$
and the first below it $(b_2, f_2)$, we interpolate linearly
in $\log(\mathrm{FPR})$ space:
\[
    b^* = b_1 + (b_2 - b_1)\,\frac{\ln f_1 - \ln\varepsilon}{\ln f_1 - \ln f_2}.
\]
Points where FPR rose relative to the previous measurement (outliers)
are excluded before interpolation.
Latency and throughput are taken from the actual measured point $(b_2, f_2)$.

\paragraph{Empty-only vs combined queries.}
To check that the ordering between filters survives a realistic
mix of empty and non-empty queries, we re-ran the same operating
points with the combined workload of
Section~\ref{subsec:queries-combined} (no truncation), at
$n = 2^{24}$ on the four SOSD datasets and $L \in \{1, 16, 1024\}$.
The ordering between filters is preserved: at $\mathcal{L} = 1$
Rosetta is fastest (Table~\ref{tab:latency-L1}) and Seg-ARE a
close second; at $\mathcal{L} \geq 16$ Seg-ARE is fastest and
Rosetta degrades steeply
(Tables~\ref{tab:latency-L16}--\ref{tab:latency-L1024}), while
SNARF stays among the slowest at every $\mathcal{L}$.
We report the empty-only numbers as headline figures because
they let FPR and latency be measured on the same query batch.
